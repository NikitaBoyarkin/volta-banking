# ⚠️ `segment_results.csv` — устаревший артефакт (stale)

Этот файл **не является авторитетным** источником p-значений для README.
Авторитетное значение — то, что посчитано по сырым данным
`data/volta_ab_experiment.csv`.

## Что расходится

Для сегмента `age_group=45+` (контроль n = 745, лечение n = 752; CR 0,5181 →
0,5319, лифт +1,4 п.п.):

| Источник | Метод | p (45+) |
|---|---|---|
| **`README.md` (авторитет)** | t-тест Уэлча по сырым данным | **0,5934 → p = 0,59** |
| README (второй способ) | χ² без поправки Йетса | 0,5931 |
| **`data/segment_results.csv` (устаревший)** | χ² с поправкой Йетса (по умолчанию в `scipy`) | **0,6294** |

`segment_results.csv` генерируется `scripts/generate_ab_data.py` →
`compute_segment_results()`, а тот вызывает `stats.chi2_contingency(table)` **без**
`correction=False`, поэтому `scipy` включает поправку на непрерывность Йетса.
Отсюда 0,6294 вместо 0,59.

## Вывод не меняется

Оба значения далеко за порогом 0,05 → эффект для 45+ статистически **незначим**
(«45+ — статистически никак»). Меняется только округление показанной цифры:
**0,59 (верно) против 0,6294 (этот CSV).**

## Что делать (рекомендация)

Перегенерировать таблицу **без** поправки Йетса, чтобы она совпала с README:

```python
_, p_value, _, _ = stats.chi2_contingency(table, correction=False)
```

(либо привести `compute_segment_results()` к тому же t-тесту Уэлча, что даёт 0,59).

**Не переписывайте этот CSV вслепую и не удаляйте его.** Причина: существующий
`generate_ab_data.py` при повторном запуске воспроизводит именно 0,6294 (а не
0,59) и заодно перезаписывает сырой `data/volta_ab_experiment.csv`, от которого
зависят другие тесты и скрипты. До осознанной правки генератора этот файл
считается устаревшим по отношению к цифре README.
