## 1. Контекст и поддерживаемое решение

**Продукт** — не необанк, а кейс-артефакт портфолио. Его пользователь описан в `docs/prd-v2.md` §5:
рекрутер (скан за 5 минут), наёмный менеджер (сигнал глубины), техлид (проверить за одну команду),
сам кандидат (готовый материал для интервью).

**Работа продукта** заявлена самим репозиторием: `docs/adr/0001-bounded-reopen-volta-2.0.md` —
*«the portfolio's job is conversion»*.

**Решение, которое поддерживает этот PRD:** что делать в следующей итерации, чтобы артефакт
конвертил, а не просто рос. Не «добавить ещё один анализ» — охват объявлен насыщенным тем же ADR.

**Допущение (помечено как Inferred):** под конверсией понимается путь читателя
«увидел → открыл борд → зашёл в репозиторий → вышел на контакт». Проверка — §8.

## 4. Требования

### REQ-001: Каждое эффект-число вычисляется из данных и публикуется в артефакт (Must)

Закрывает PA-01, PA-02, PA-03. Один прогон `make all` должен порождать машиночитаемый источник
всех чисел, которые цитирует README.

- AC1: `volta_retention_analysis.py` строит LTV-прогноз из `data/cohort_retention_matrix.csv`, а не из `PARAMS["*_curve"]`; литеральные кривые удалены.
- AC2: агрегат «€X/год» считается в коде из числа активируемых пользователей, ARPU и кривых; ни одного числового эффекта в виде строки.
- AC3: `outputs/impact.json` содержит ключи `ab_cumulative_12m_revenue_eur`, `ab_roi_multiple_12m`, `retention_incremental_ltv_eur`, `kyc_lift_pp` с полями `value` и `source_file`.
- AC4: тест сверяет числа из `impact.json` с числами в `README.md` и падает при расхождении.
- **Проверка:** `uv run python scripts/volta_retention_analysis.py && uv run python scripts/volta_ab_testing.py && uv run pytest tests/test_impact_artifacts.py -v`

### REQ-002: Порог покрытия становится гейтом (Must)

Закрывает PA-05. Одна строка, но убирает дрейф молчаливой деградации.

- AC1: `addopts` содержит `--cov-fail-under=90`.
- AC2: локальный прогон ниже порога завершается кодом 1.
- AC3: бейдж покрытия в README заменён на значение из артефакта (`impact.json` или CI-артефакт), либо удалён.
- **Проверка:** `uv run pytest -q; echo $?` → 0 при текущих 97%; `uv run pytest --cov-fail-under=99; echo $?` → 1

### REQ-003: Убрать неиспользуемые генераторы и датасеты (Should)

Закрывает PA-07. `make data` не должен производить то, что никто не читает.

- AC1: `volta_feature_events.csv`, `volta_referrals.csv`, `volta_campaigns.csv` и их генераторы удалены **или** подключены к анализу, который их использует.
- AC2: `make data` завершается без создания файлов, отсутствующих в графе «датасет → читатель».
- AC3: тест проверяет, что каждый файл в `data/*.csv` упоминается хотя бы в одном анализе или тесте.
- **Проверка:** `uv run pytest tests/test_dataset_consumption.py -v`

### REQ-004: Гейт «число в README ↔ источник» (Should)

Закрывает PA-04, PA-08. Делает невозможным повторить историю с двумя евро-числами.

- AC1: README не содержит числового эффекта, отсутствующего в `impact.json`.
- AC2: у пары €208,5K / €227K есть явное определение в тексте (что именно и за какой период), либо одно из чисел удалено.
- AC3: `data/segment_results.csv` удалён или перенесён в `data/legacy/` с явной пометкой.
- **Проверка:** `uv run pytest -q -k readme` (тест из REQ-001 AC4 расширен на все эффект-числа)

### REQ-005: Типы на всех 23 анализах (Should)

Закрывает PA-06. Флагманские модули не должны быть вне проверки типов.

- AC1: `[tool.mypy] files` содержит все `scripts/volta_*.py` (23) либо использует `packages`/`mypy_path` вместо ручного списка.
- AC2: `uv run mypy` остаётся зелёным; легаси-модули, если их нельзя типизировать, помечены `# mypy: ignore-errors` явно и перечислены в одном месте.
- AC3: CI падает, если новый `volta_*.py` не покрыт.
- **Проверка:** `uv run mypy 2>&1 | tail -1` → «Success: no issues found in ≥23 source files»

### REQ-006: Северная метрика артефакта и инструментация пути читателя (Must)

Закрывает PM-01, PM-03, PA-09. Без этого улучшения выше нельзя оценить.

- AC1: в `docs/prd-v2.md` §4 Goal A появляется одна измеримая метрика с числом (например: доля читателей, дошедших от лендинга до репозитория за 30 дней) и целевое значение.
- AC2: на лендинге сайта событие открытия борда и клика в репозиторий инструментированы (PostHog), схема событий записана в репо.
- AC3: через 30 дней после релиза есть отчёт с числом; отсутствие данных трактуется как провал гейта, а не как «нет сигнала».
- **Проверка:** `posthog`-запрос по событиям за 30 дней возвращает ненулевое число; ссылка на дашборд лежит в `docs/`.

### REQ-007: Развести роли с соседними репозиториями (Could)

Закрывает PM-02, PM-04. Дешёвая правка нарратива, а не кода.

- AC1: в README один абзац объясняет разделение: Volta — флагманский сквозной кейс; `ab_test` — инструментарий метода; `causal-uplift` — исследование uplift.
- AC2: «23 проекта» остаётся как факт охвата, но перестаёт быть главным аргументом в первом экране.
- AC3: каждый sibling-репозиторий либо ссылается на Volta как на флагман, либо явно себя позиционирует иначе.
- **Проверка:** ревью README человеком (механизма нет — это осознанно слабейший класс по `claim-mechanism`).
