## Executive Summary

- **Датасет:** `data/charts/funnel.csv` — 10 000 строк × 12 колонок, синтетика (seeded), период `2024-07-01 … 2024-07-28`.
- **Grain:** одна строка = один пользователь (install-level); `user_id` уникален (10 000/10 000), полных дубликатов 0.
- **Целевая метрика:** `first_tx` (install → первая транзакция) — доля **12,69 %**, 95 % CI Уилсона `[12,05 %, 13,36 %]`; распределение бинарное, скошенность не применима.
- **Главный разрыв:** канал — `paid_social` **6,1 %** против `referral` **17,8 %** (**×2,92**); разрыв устойчив к стандартизации по device+age (не артефакт состава).
- **Состояние данных:** чисто по структуре; единственная ожидаемая проблема — 87,3 % пропусков в `first_tx_date` (структурные, не случайные).
- **Главный вывод:** узкое место онбординга — шаг **KYC complete** (56,6 %, отвал 43,4 %); A/B подтверждает причинный лифт прогресс-бара **+5,72 п.п.** (p ≈ 7·10⁻⁹), но эффект **гетерогенен** — 35–44 и Android отвечают, 45+ стоит (p = 0,63).

## Распределения

Все шесть колонок-шагов — бинарные флаги, поэтому «форма распределения» описывается долей успеха, а не скошенностью. Для `first_tx` доля = **12,69 %** (1 269/10 000) — редкое событие; для сравнения сегментов корректно использовать пропорции с интервалами Уилсона, а не среднее. Числовые колонки A/B: `pre_kyc_rate` ≈ нормальна (skew −0,06), `revenue_30d_eur` слабо скошена (0,27), `churned_30d` скошена (1,73) — бинарный guardrail.

**По возрасту:** 25-34 13,07 % … 45+ 12,18 % (×1,07) — практически плоско.

## Findings (E / H / R)

### Finding 1: узкое место онбординга — шаг KYC complete

**Evidence:**
- `kyc_start → kyc_complete` = **56,56 %** (2 781/4 917), 95 % CI Уилсона `[55,17 %, 57,94 %]` — самый низкий шаговый переход; отвал **43,44 %**.
- Следующий по слабости шаг `card_ordered → first_tx` = 63,67 %; остальные ≥ 67 %.
- В абсолютных числах больше всего теряется на `app_install → registration` (−2 682), но относительное узкое место — именно KYC (борд `docs/board/volta_board.html` маркирует 56,6 %).

**Hypothesis:**
- H1: «Если упростить KYC (прогресс-бар), конверсия шага вырастет → больше активаций».
- H2 (альтернативная): узкое место — доверие/документы у отдельных сегментов, а не UX; тогда общий фикс сработает неравномерно. `[❓ требует валидации]`

**Recommendation:**
- Действие: выкатить прогресс-бар KYC на 100 % (уже подтверждено экспериментом, Finding 3).
- Рычаг: `conversion ↑`
- Сценарий проверки: A/B (уже проведён, см. ниже) + HTE-мониторинг по возрасту/устройству.
- Приоритет: **H**

### Finding 2: главный сегментный разрыв — канал привлечения (paid_social vs referral)

**Evidence:**
- `paid_social` 6,11 % против `referral` 17,82 % — разрыв **×2,92**; `paid_social` несут 25,5 % установок, но лишь 12,3 % первых транзакций.
- Разрыв устойчив к стандартизации по device+age (6,11 % / 17,82 % без изменений) — не артефакт состава.
- `app_store` 8,22 % — второй слабый канал.

**Hypothesis:**
- H1: «Если перераспределить бюджет в referral/organic, blended-конверсия и CAC улучшатся».
- H2 (альтернативная): `paid_social` привлекает низконамеренный трафик по определению — разрыв сохранится при любом UX-фиксе. `[❓ требует валидации]`

**Recommendation:**
- Действие: пилот перераспределения бюджета paid_social → referral; отдельно QA-спринт для `app_store`.
- Рычаг: `conversion ↑` (и `CAC ↓`)
- Сценарий проверки: гео/канальный до-после с контролем на состав.
- Приоритет: **M**

### Finding 3: A/B подтверждает причинный лифт KYC — README воспроизведён точно

**Evidence:**
- Control 55,82 % (2 791/5 000) → Treatment 61,54 % (3 077/5 000): **+5,72 п.п.**
- χ²=33,50, **p ≈ 7,1·10⁻⁹** (< 0,0001); z=5,82; нормальный 95 % CI лифта `[+3,79; +7,65]` п.п., bootstrap `[+3,78; +7,66]` — ноль не пересекается.
- SRM: χ²=0, p=1,000 (нет). Guardrails: `churned_30d` ниже в treatment (15,9 % vs 18,6 %, p=0,0003), `revenue_30d_eur` выше (€12,54 vs €11,68, p<0,0001) — нарушений нет.

**Hypothesis:**
- H1: «Прогресс-бар причинно повышает завершение KYC» — согласуется со случайным дизайном, SRM и направлением guardrail'ов.
- H2: эффект частично объясняется «новизной»/Хоторном за 28 дней — `[❓ требует валидации]` долгосрочно.

**Recommendation:**
- Действие: выкат на 100 % (гейт пройден: p<0,05, лифт ≥ MDE +5 п.п., нет SRM).
- Рычаг: `conversion ↑`
- Сценарий проверки: holdout на 5 % после раската для контроля долгосрочного эффекта.
- Приоритет: **H**

### Finding 4: эффект гетерогенен — ядро 35–44 и Android отвечают, 45+ стоит

**Evidence:**
- Лифт по возрасту: `35-44` **+11,05 п.п.** (p<0,001), `18-24` +5,29 п.п. (p=0,018), `25-34` +3,14 п.п. (p=0,065), `45+` **+1,38 п.п. (p=0,63)**.
- По устройству: `android` **+9,07 п.п.** (p<0,001) против `ios` +1,56 п.п. (p=0,33).
- По каналу: `referral` +10,05 п.п., `google_play` +7,79 п.п. — значимы; `app_store`/`website` — нет.
- ⚠️ README утверждает для 45+ «p = 0,59» — по данным `volta_ab_experiment.csv` (и `segment_results.csv`) **p = 0,6294**. Minor MISMATCH (см. Truth check).

**Hypothesis:**
- H1: «Барьер 45+ — доверие, а не интерфейс, поэтому UX-фикс им не помогает».
- H2 (альтернативная): недостаточная мощность в подгруппе 45+ (n=1 497) — эффект есть, но не детектируется. `[❓ требует валидации]`

**Recommendation:**
- Действие: сегментный оффер/доверительный трек для 45+ вместо generic-прогресс-бара.
- Рычаг: `conversion ↑`
- Сценарий проверки: отдельный A/B на 45+ с MDE под размер подгруппы.
- Приоритет: **M**

### Finding 5: денежный эффект воспроизводится, но это модель, а не наблюдение

**Evidence:**
- Из допущений проекта (LTV €85, 50 000 установок/мес, kyc_start 0,492, card 0,718, tx 0,637): доп. активации 643,6/мес → **€54 703/мес → €656 440/год**, ROI = **43,76×** на €15 000.
- Шаговые доли модели совпадают с воронкой (0,717/0,637/0,492).
- ⚠️ Величина **не** наблюдаемое измерение: это проекция при зафиксированных допущениях LTV и объёма.

**Hypothesis:**
- H1: «При допущениях проекта денежный эффект ≈ €656K/год».
- H2 (альтернативная): реальный LTV/объём отличаются → эффект смещён пропорционально. `[❓ требует валидации]`

**Recommendation:**
- Действие: публиковать €656K как «модель при явных допущениях», а не как факт.
- Рычаг: `revenue ↑`
- Сценарий проверки: сверка LTV €85 с фактической выручкой активированного пользователя.
- Приоритет: **M**

## Что не вошло

- **Временные причинные утверждения** (фикс KYC «в сентябре 2024» → retention) — воронка покрывает только июль 2024; причинность по времени вне EDA (это `volta_causal_kyc.py`, difference-in-differences).
- **`volta_causal_kyc.csv`, `volta_dormant_winback.csv`, `volta_premium_offers.csv`, `volta_fx_sourcing.csv`, `volta_clv_customers.csv`** — не профилированы в волне 2 (22 датасета проекта; здесь первичный + опорные). Их headline-числа помечены NOT-CHECKABLE.
- **Anchor CAC LTV/CAC vs scale** — требует greedy-распределения каналов, а не бакетной сортировки; точное 1,76/70K не воспроизведено.
- **Согласованность `docs/board/volta_board.html`** с данными — вне периметра (запрещено трогать `docs/board/`), но шаговые конверсии борда сверены и совпадают.
- **Двухфайловая воронка**: `data/charts/funnel.csv` и `data/volta_funnel_data.csv` — один и тот же результат (все шаги/категории идентичны на 10 000 строк), различается только точность `install_date` (микросекунды vs наносекунды). Дублирование не расхождение, но создаёт риск «какой файл канон». Не исправлял (вне периметра).
- **`pre_kyc_rate` как ковариата** — CUPED-снижение дисперсии всего 0,07 % (ρ²≈0,0007 на control): ковариата практически не предсказывает исход. Проверка генератора вне периметра; отмечено как P2.
